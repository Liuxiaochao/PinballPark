1设计目标与原则

1.1 设计基调

"街机厅里的弹珠机" —— 温暖、明亮、有手感的休闲街机风。整体走浅色舒适应用壳 + 沉浸式暗色游戏舞台的双层结构：大厅/商城/我的用浅色降低长时间浏览疲劳（契合休闲解压定位），进入游戏局内时板面落入深蓝渐变"机器腔体"舞台，让钉板、亮灯出口与弹珠高对比跳脱。色彩以蓝（品牌信任）为主、金（弹珠/中奖）为强调、绿（命中庆祝）与紫（积分卡）为辅助语义色。

1.2 五大原则（承接铁律与产品目标）

原则落地要求
① 结果可信、不可伪造HUD/倍数/亮灯出口只展示服务端下发的权威数据；任何"中奖特效"不得早于 /game/launch 返回出现，杜绝客户端暗示可控结果（呼应架构铁律一）。
② 即时反馈每次投珠、拉杆、落口、掉珠、出卡、领珠、翻倍都有对应微动效 + 数字滚动，爽感连续不空窗（北极星指标依赖）。
③ 性能优先首屏 < 3s、移动端演出 ≥ 30fps；极端奖励（N 高达 1980）禁止生成全部物理刚体，走对象池 + 数字累加（架构 §6.3）。动效不得阻塞主线程。
④ 多端一致、一次开发Cocos 一套代码出三端，UI 用相对单位 + 安全区适配，平台差异（导航栏/广告样式）收敛到适配层，视觉规范三端统一。
⑤ 克制合规不出现"花钱必中"暗示；概率公示入口常驻；未成年提示明显；沉没明确告知（"本局投入已沉没"）。

2.3 间距 / 圆角 / 阴影

  • 间距基准 4px：xs4 / sm8 / md12 / lg16 / xl24 / xxl32。布局栅格用 8 的倍数。
  • 圆角：按钮/卡片 12px；小标签/芯片 999px；弹层 Sheet 顶部 16px。
  • 阴影（浅色壳）：卡片 0 1px 3px rgba(0,0,0,.06)；浮起按钮 0 6px 16px rgba(24,95,165,.24)。克制：避免重投影"布丁感"，靠描边 + 浅底色分层。

性能分级（同一套 UI，按设备降级）：
  • 高配：钉阵 60 钉、出珠盒子全粒子阴影、亮灯 glow 全开。
  • 中配：钉阵 45 钉、盒子阴影降采样、glow 减半。
  • 低配：钉阵 30 钉、关闭盒外阴影、溢出珠用占位 sprite + 数字滚动替代（仍走物理但减刚体数）。
分级由 Cocos 启动时按 GPU/内存探测，不影响交互与数值（仅演出精度）。

4页面设计规范（含线框）

线框为布局示意（非高保真），标注元素与上游决策对应关系。所有"数字展示"遵循 PRD §5.3 信息展示规格。

4.1 启动 / 登录

登录即发 30 颗（API §登录即发，open 不再发）；隐私协议勾选强制。

4.2 大厅 Lobby

顶部常驻"弹珠/积分"余额条；主按钮"开始游戏"；金刚区含概率公示常驻入口；底部常驻"领珠 +88 / 今日剩 N/6"按钮（达上限置灰"明日再来"）。

4.3 游戏局内 Game（核心）

图层关系（来自 PRD §5.3 / 架构 §3 / §4）：板面（钉板+亮灯出口+球）在板面局部坐标做 2D 物理仿真，渲染时施加 机台后仰 30° 的真实透视倾斜（perspective + rotateX(30°)）——板面有纵深、球沿后仰面板"下坡"滚动，符合真实柏青哥/老虎机机台观感（非平面 2D 旋转）；HUD 文字与拉杆/加注按钮属于屏幕正向独立图层，不随板倾斜；倍数数字用屏幕正向 overlay 叠加保证可读。权威视觉稿见 ui-game-machine-mockup.html（含机柜质感与倾斜对比开关）。
板面 30° 透视倾斜（机台后仰，真实机台观感；下图为平面示意，权威渲染见 机台视觉稿）；顶部 HUD 与底部"加注/拉杆"为屏幕正向独立图层，不随板倾斜；亮灯出口高亮、暗口置灰；出珠盒子位于底部承接口。
  • 投珠输入：默认 5，±步进 / 滑块 5–99，"最大"快捷；实时显示"命中预计得珠 = 投入 × 倍数"（PRD §5.3）。
  • 倍数大字：板顶"本局 ×8"屏幕正向 overlay；亮灯出口仅高亮"可中区"，不重复标倍数（PRD §5.3）。
  • 拉杆：按压蓄力、松手发射、移出命中区/进取消区松手即取消，不扣珠（PRD §5.3）。蓄力仅演出、不影响落点（架构 §5）。
  • 加注：常驻醒目"再投珠加注"按钮（弹珠图标 + 实时"预计奖励"），点开追加，受余额与 ≤99 约束；加注后 HUD"本局投入"→"有效投入"并高亮跳动（PRD §5.3/§4.4）。

4.4 结果展示区 Result（无结算弹窗）

沿用 PRD 决策：一局结束、球落定后不弹结算弹窗，结果直接显示在结果区。命中："获得 N 颗弹珠 + M 张积分卡"伴积分卡出卡动画；未命中："本局投入 X 颗已沉没"。同区常驻"再来一局 / 看视频 ×2（限频）/ 去商城"与"领珠"按钮。按钮层级采用方案甲（主按钮=看视频 ×2）。
命中：出珠盒子逐颗掉落至 N（容量 60，超出物理溢出），积分卡回弹出卡动画；主按钮"看视频 ×2"最大最亮（方案甲）。未命中：无 ×2、明确沉没提示。

4.5 商城 Mall

  • 顶部 Tab 按兑换所需卡数 K 分层：虚拟(5) / 小实物(20) / 中实物(50) / 实物(80) / 高实物(120)（数值文档 §4.1）。
  • 商品卡显示"所需 K 张卡"、积分价（=K×10）、"是否够兑"实时态；缺货/下架清晰。
  • 兑换 → 风控 → 扣卡 → 第三方下单 → 订单状态；"我的订单"展示状态与（实物）物流。

4.6 我的 / 订单 Profile

  • 积分明细（卡数 / 累计积分）、订单状态机（created→…→done/failed）、概率公示入口、设置（含未成年模式开关）、退出。

4.7 概率公示（合规常驻）

入口常驻大厅金刚区 + 设置页；点击弹 Sheet 展示倍数档 ×2/×4/×6/×8/×16/×32 与各自出现概率（来自数值文档 §1.2 权重折算）。这是合规红线（PRD §9.1），不可移除或深藏。

4.8 未成年 / 设置

  • 首次进入弹未成年消费/时长提示；设置可开启"青少年模式"（限时长、隐藏商城高价值档）。

5核心交互动效规格

5.1 拉杆蓄力

  • 手指按下：弹簧杆压缩（scaleY 0.8→1.0 随蓄力），蓄力环 0→100% 线性填充（跟随手指位移或按住时长）。
  • 松手：发射，弹珠从杆口以初速（区间内抖动）弹出，杆回弹微动。
  • 取消（移出命中区/进取消区松手）：杆回弹、无发射、无扣珠、回到 BET_SET（架构 §3.2）。不触发任何中奖演出。

5.2 亮灯出口刷新

  • 开局拿到 litExits 后，对应出口 200ms glow 脉冲点亮（#FFD66B），暗口保持 #2A3650 置灰；点亮带轻微"通电"音效（可选）。

5.3 出珠盒子掉落 + 物理溢出

严格遵循架构 §6：命中后珠子从落定亮灯出口逐颗掉落入盒，每颗为真实 Box2D 刚体（与板面同物理世界、局部竖直重力），盒计数 +1 至 N；满 60（CAP）后继续生成的珠从盒沿真实溢出滚落消散（非脚本）。权威计数 = 服务端 N，与物理珠解耦；N 大（≤1980）仅生成有限物理珠（对象池 60+溢出≤20）+ 数字滚动收尾，防掉帧。看视频 ×2：N→2N，补播额外 N 颗走同样逻辑。下落节奏按 N 分级（小则快落、大则喷落加速）。

5.4 积分卡出卡

  • R≥40 命中后，积分卡从结果区右侧"弹卡口"回弹飞出（420ms cubic-bezier(.34,1.56,.64,1)），伴随 +1 数字滚动；多张则连发（封顶 5）。

5.5 看视频 ×2 翻转

  • 点主按钮 → 全屏广告（平台接管，Z=100）→ 服务端 /ad/callback 验真成功返回 → 奖励数数字滚动翻转 N→2N、出珠盒子补播额外 N 颗、积分卡（若有）不重复发（仅首次结算发卡）。失败时回退 N 并 Toast"未获得翻倍"。

5.6 常驻领珠按钮

  • 点"领珠 +88" → 广告 → 验真 → 余额数字滚动 +88、按钮"今日剩 N/6"递减；达 6 次置灰"今日已达上限，明天再来"，不触发视频（API 频控）。

5.7 通用反馈

  • Toast：160–220ms 淡入，2s 自动消失，位于 Z=80。
  • 数字滚动：tabular-nums，缓动 220ms，避免抖动。
  • 按钮态：默认 → 按下（#0C447C/scale .97）→ 禁用（置灰 + 文案说明）。

7图标与插画

  • 图标风格：线性 + 圆角（2px 描边、24×24 网格），语义色填充；关键图标：弹珠（金圆）、积分卡（紫卡）、领珠礼物、视频、商城袋、我的头像、概率公示(i)、签到日历。
  • 插画：大厅主视觉用扁平街机风插画（弹珠机轮廓 + 星光）；空态用轻量单色插画；庆祝用粒子/星光（命中全屏庆祝限高倍 ×16/×32，避免滥用）。
  • 弹珠质感：径向渐变 #FFF6D8→#F5A623，统一全端。

8无障碍与合规

  • 对比度：正文 ≥ 4.5:1；亮灯出口高亮与暗口置灰对比明显，防色盲误读（出口加形状/位置区分，不只靠颜色）。
  • 动效偏好：尊重系统"减少动态效果"开关，关闭非必要粒子/回弹。
  • 合规常驻：概率公示入口不可移除；未成年提示显著；沉没明确文案；不暗示"付费必中"。
  • 触控热区：主操作 ≥ 44×44pt，拉杆/加注按钮足够大防误触。
