按「价值安全边界」优先排序：服务端判定（命中/落点/奖励/卡）为唯一权威，一切客户端表现与本地计算不得参与价值判定。测试分层如下：

层级范围主要手段对应章节
单元命中算法、发卡规则、K 分层、签名、状态机Go 表驱动单测 + 蒙特卡洛脚本§3 / §5

性能演出帧率、N=1980 边界、并发、延迟压测（k6/自研）+ 真机帧率采集§4
安全签名、防重放、防客户端伪造、频控模糊测试 + 逆向尝试 + 审计§5

2功能测试 · 四段事务状态机

一局状态机：open(bet_locked) → [bet] → launch(launched) → settle(settled)；异常路径 bet_locked→aborted（锁超时）。单用户同时仅一局（game_lock:{uid}，TTL 30min）。

用例标题前置 / 步骤预期级别
FUN-01完整一局happy path余额≥5 → open(5) → launch → settle余额扣 5 后按结果增减；game_lock 在 settle 后释放；status=settledP0
FUN-02open 锁投入余额 25，open(bet=5)响应 balance=20；bean_ledger 增 type=open_lock 5；game_rounds.status=bet_lockedP0
FUN-03加注上限与锁open(5) 后 bet(addBet=10)，再 bet(addBet=90)第一次 effectiveBet=15；第二次拒（effective_bet+addBet>99），返回 4xxP1
FUN-04launch 权威判定launch(roundId)返回 hit/targetExitId/rewardBeans/cards/multiplier/rtpApplied；chargePower 仅记录不参与判定；status=launched 且未发放P0
FUN-05settle 幂等入账同一 roundId 连续 settle 两次第二次返回首次结果；bean_ledger/point_ledger 仅一次写入；无重复发奖P0
FUN-06并发锁同一用户在局中进行中再发 open返回 40903 game_locked；不创建新局、不重复扣币P0
FUN-07断线恢复-已结算settle 后断线重连，调 GET /game/round/{id}status=settled, settleDone=true；客户端直接展示，不重复 settleP0
FUN-08断线恢复-已发射未结算launch 后断线，重连status=launched；客户端播放落点演出后调 settleP1
FUN-09锁超时回滚open 后 30min 内未 launch/settlegame_lock TTL 触发 → status=aborted，锁释放，bet 经 bean_ledger(type=open_refund) 回滚；不丢资产P0
FUN-10暗口沉没未命中局targetExitId ∈ 暗口集（litExits 之外独立沉没通道）；rewardBeans=0, cards=0P1
对齐 API §3：四段事务价值在 launch 一次定死、settle 才入账；chargePower 仅演出。所有「写价值」接口以 roundId 行级锁 + 状态机去重，客户端可安全重试。

用例攻击 / 场景预期级别

SEC-04伪造命中算法本地计算 P(hit) / 选出口无效；命中仅由服务端密码学安全随机源决定P0
SEC-05chargePower 作弊拉杆力度影响判定 → 无效（仅演出）P1
SEC-06广告回调伪造伪造「看完广告」直接领珠 → 必须经平台 server-to-server 回调验真（adModule 验签）才发奖P0
SEC-07领珠频控绕过尝试第 7 次领珠 → 拒绝；客户端改本地时钟无效（以服务端日期为准）P1
SEC-08并发双 settle 刷奖同 roundId 并发 settle → 仅一次入账（状态机去重）P0

8埋点与监控

对齐 PRD §11「三大漏斗」：广告 / 局内 / 兑换。以下事件须完整且看板可见：

  • 广告漏斗：ad_request → ad_show → ad_reward(server_verify) → beans_grant；scene ∈ {sign, high_multiplier} 触发时机可溯。
  • 局内漏斗：open → bet(可选) → launch → settle → beans/cards 变化；含 rtpApplied 与 multiplier 维度。
  • 兑换漏斗：exchange_enter → risk_pass → deduct_card → fulfill → order_status（Exchange 模块上线后补全）。
  • 监控告警：实时 RTP 偏离阈值（>±3%）告警；单用户异常高频局 / 异常大额奖励审计；game_lock 堆积告警。

10测试环境 / 数据 / 工具

  • 环境：本地（SQLite 影子）+ 测试服（MySQL/Redis 同构）+ 灰度（1% 流量）。
  • 造数：固定种子复现特定局（roundId 可回溯）；RTP/权重参数化注入，便于 NUM 回归。
  • 工具：Go Testify（单元）、k6（压测）、Postman/Newman（API）、economy_sim.py（经济回归）、真机帧率采集 + 截图 diff（渲染）。
  • 对账：每日 bean_ledger + point_ledger 与余额快照对账，差异 >0 即告警。

11缺陷分级与发布门禁

级别定义处理
P0价值安全 / 数据丢失 / 无法开局 / 合规缺失阻塞发布，24h 内修复
