1产品概述与目标

1.1 产品定位

将线下"弹珠乐园"实体游艺机的核心爽点（投珠 → 拉杆弹射 → 钉板碰撞 → 落入亮灯出口 → 倍率奖励）搬到线上，做成一款轻量、即玩即走、靠广告变现的多端休闲游戏。线上化后用激励视频广告替代实体机的投币收入，用积分兑换实物替代实体机的"退币/彩票"奖励，保留随机倍率带来的兴奋感，同时规避付费博彩合规风险。

1.2 一句话描述

"拉杆弹珠、落口中奖、看广告攒珠、积分兑好礼——一款零门槛、靠手气与运气解压的弹珠休闲游戏。"

1.3 商业目标（北极星与约束）

  • 北极星指标：人均广告有效观看次数（兼顾留存与变现）。
  • 生命线约束：人均广告收益 ≥ 人均积分产出成本 × 安全系数（≥1.2），否则触发经济模型闸门（见 6.5）。这是能否长线盈利的核心判据。
  • 合规底线：弹珠不可现金购买、积分/奖品不可反向兑换现金（详见第 9 节）。

1.4 已确认的关键决策（来自框架大纲）

维度决策
目标平台多端：微信小游戏首发，iOS/Android App 二期，H5 可选传播

2用户画像与场景

核心用户：休闲解压型（占比预估 60%）

  • 18–40 岁，通勤 / 午休 / 睡前碎片时间
  • 诉求：轻操作、强反馈、有惊喜感，不重度
  • 动机：攒珠兑实物、看视频白嫖奖励

次级用户：收集成就型（占比预估 30%）

  • 喜欢积分进度、兑换清单、每日签到闭环
  • 诉求：确定性成长感、商城可达成

边缘用户：羊毛/尝鲜型（占比预估 10%）

  • 冲着高价值实物来，易被风控识别（见 9.2）
  • 诉求：用最少时间薅到实物；是风控与成本闸门的重点对象

4.2 开局与投珠

  • 玩家设定本局投入弹珠数（默认建议值 5，范围 5–99，受余额约束）。
  • 点击"开始"后，客户端向服务端请求开局，服务端在事务内锁定投入弹珠（先扣后结算，防并发），并下发：当局倍数档 ×N、亮灯出口集合（见 4.3）。
  • 客户端展示亮灯出口与倍数，进入"拉杆"阶段。

4.3 倍数与出口（12 出口方案）

倍数档亮灯出口数 / 12难度处理
×25–6 个低保底档，高频出现
×3 / ×53–4 个中常规档
×8 / ×102 个较高兴奋点
×15 / ×201 个高稀有档，命中触发全屏庆祝
判定逻辑（结果可控）：服务端先决定本局是否命中及命中哪个亮灯出口，再据此引导客户端物理落点。具体 RTP/权重由数值文档定义；客户端只负责"看起来自然地"把珠子送到目标出口。未命中任何亮灯出口 → 本局投入弹珠沉没（不返还）。

4.4 再投珠加注（核心特色）

  • 在"拉杆"前，玩家可追加投入弹珠，提高本局命中后的奖励珠基数。
  • 加注后，本局有效投入 = 初始投入 + 加注；奖励珠 = 有效投入 × 倍数。
  • 加注上限与单局投入上限一致（≤99 颗），且受余额约束；加注不额外改变倍数或出口。
  • 加注入口需有醒目反馈，是提升单次投入与兴奋感的关键设计位。
  • 服务端一致性：加注在"拉杆"前发起，客户端需再次请求服务端在事务内追加锁定加注弹珠（防并发超投）；服务端返回更新后的有效投入与"预计奖励"，客户端刷新后再进入拉杆阶段（呼应 4.6 时序：落点 targetExitId 在拉杆时请求）。

4.5 结算与积分卡

  • 命中亮灯出口：奖励珠 = 有效投入 × 倍数，入弹珠账本。
  • 积分卡产出（易触达规则）：单局命中奖励珠 R，仅当 R ≥ 40（可配置门槛）才发卡；卡数 = min(5, floor(R / 40))（40~79→1 张、80~119→2 张……1500+→5 张封顶）。R < 40 不发卡。1 张积分卡 = 10 积分。
  • 兑换所需卡数 K 分层（经济兜底，详见《玩法数值设计文档》）：虚拟引流档 5 / 小实物 20 / 中实物 50 / 实物主档 80 / 高实物 120。卡负责"反馈频次"、K 负责"经济平衡"，两者独立可调。
  • 弹珠（游戏内循环资源）与积分（兑换资产）单向转换、不可逆流：只能 珠→命中→积分，积分不能变回珠。
数值已定（见《玩法数值设计文档》v1.1）：目标 RTP = 0.90（新手保护期更高）；倍数 ×2~×20 加权（均倍 4.37）；命中率反解 P(hit)=RTP/M；积分卡发卡门槛 40 颗（R≥40 才发卡，min(5, floor(R/40))），兑换按 K 分层（5/20/50/80/120）。激励视频领珠 88 颗/次、每日 6 次；每日登录 30 颗；免费投入池约 558 颗。经仿真验证满足生命线 广告收益 ≥ 积分成本 × 1.2（重度 1.26× / 轻度 1.38×）。新手保护曲线（前 5 局 RTP 1.50、第 6–15 局线性递减至 0.90、第 16 局起稳态）见数值设计文档 §7；出珠盒子显示容量 60 颗（纯显示参数，见数值设计文档 §6）。

4.6 落点还原机制（物理一致、结果受控）

物理一致性结论：碰撞全程基于真实物理引擎（Box2D），无瞬移、无穿模、无反物理加速。与实体机的唯一区别：实体机靠固定钉板几何把落点分布编码成目标返奖率；线上版因需按玩家个体做 RTP 调控（新手保护、盈亏池），改为在保持物理演出真实的前提下，对下半场落点做有界引导。该引导幅度被限制在"自然弹跳方差包络"内，观察者无法与真实混沌弹跳区分，故物理自洽。

两阶段仿真

  • 阶段① 自由碰撞区（真物理）：弹簧杆发射 + 钉板随机弹跳，真实 Box2D 仿真，玩家获得真实手感与不可预测性。
  • 阶段② 引导路由区：球越过"路由控制线"后进入由真实墙体构成的通道（物理碰撞）；在通道入口施加一个有界横向引导力，将球送入后端指定的目标出口通道。命中→目标亮灯出口；不中→引导至某个暗口通道。

为什么不是"造假"

  • 所有运动均遵守对真实几何的碰撞；唯一的自由量是一个幅度受控、落在方差包络内的横向修正，等价于真实机器里"钉板几何本身对落点的塑形"。
  • 底部每个出口上方必须预留真实的开放通道，引导轨迹贴着通道走，杜绝视觉穿帮。

拉杆手感 vs 结果边界

  • 玩家拉杆力度真实影响发射初速（在区间内抖动），但不影响最终落点——结果由后端在"拉杆"请求时即已定好。这是运气游戏，拉杆提供仪式感与手感，不提供操控权。

时序配合

  • 倍数 + 亮灯出口在"开局"下发；具体落点 targetExitId 在玩家"拉杆"动作时单独请求后端，前端在物理仿真开始前拿到目标，引导力方可正确施加（当前 4.2 仅在开局下发倍数+亮灯出口，落点请求须在"拉杆"时新增为独立接口，详见《服务端 API 设计文档》）。

更纯物理的备选方案

  • 发射参数偏置法：后端按固定钉板布局反解（力度/角度），使真实物理"自然"落进目标出口（需离线求解/查表，玩家拉杆幅度须限制在该可解区间内）。优点：100% 物理、零引导力；缺点：需求解器、玩家操控自由度下降。架构上两种可并存，首发优先实现"有界引导"。

4.7 板面 30° 倾斜的物理约束

倾斜定义（已确认）：板面相对手机屏幕平面绕 Z 轴旋转 30°（屏幕平面内的 2D 旋转，非 3D 透视变形）。即板在屏幕上呈 30° 倾斜的平行四边形，而非被压扁的透视。
  • 推荐实现：物理在板面局部坐标跑，渲染时整体旋转 30°。物理世界内板面轴对齐、重力为局部竖直 (0,−g)；钉阵、通道墙、出口均在轴对齐局部坐标内定义（易编排）；仅渲染层对"板面 + 球"整体施加 30° Z 旋转显示。此方式下 4.6 的引导力即局部 X 轴修正，无需在屏幕 / 板面坐标系间换算，最简单且物理自洽。
  • 视觉正确性：局部空间球竖直下落，经 30° 渲染旋转后，视觉上即沿倾斜板的"下坡"方向滚动，与真实倾斜板受重力分量漂移的观感一致。
  • 漂移方向：由旋转手性决定（顺时针 30° → 视觉向右下漂）。默认顺时针，可在美术阶段微调；物理侧仅改渲染旋转角（若改用旋转重力方案则同步调整重力向量）。
  • HUD 与板面分层：投珠数 / 倍数 / 奖励 / 剩余等文字与拉杆、加注按钮属于屏幕正向的独立图层，不随板旋转；亮灯高亮画在板面上（随倾斜），倍数数字用屏幕正向 overlay 叠加保证可读。
  • 钉板布局：交错钉阵（类高尔顿板），钉距 / 密度调手感；路由区上方以真实通道墙替代钉阵（呼应 4.6），引导力仅把球扶进选定通道口。

5.3 核心交互细节（已确认）

本节为已确认的核心交互决策，作为客户端交互实现基线；视觉风格（配色 / 动效 / 美术）留待《UI-UX 设计文档》。

拉杆操作（触屏优化）

  • 交互：按压蓄力、松手发射、支持取消。玩家按住屏上"弹簧杆"按钮，蓄力环 / 条实时填充；松手即发射。
  • 取消：蓄力过程中将手指移出按钮命中区（或拖入取消区）后松手，视为取消——不发射、不扣弹珠、回到待发射状态。
  • 手感边界：蓄力仅影响发射演出（力度在区间内抖动），不改变后端已定落点；取消不消耗任何资源。

再投珠加注入口

  • 常驻醒目按钮：拉杆前始终显示"再投珠加注"（弹珠图标 + 实时"预计奖励"），强化核心特色与转化。
  • 点开输入追加量，受余额与单局上限（≤99）约束；有效投入与"预计奖励 = 有效投入 × 倍数"实时刷新。

各界面交互基线（对应 5.1 / 5.2）

  • 大厅：顶部常驻"弹珠 / 积分"余额条；主按钮"开始游戏"进投珠面板；面板默认 5 颗，滑块 / ± 设 5–99，"最大"快捷，实时显示"命中预计得珠"。
  • 无结算弹窗：一局结束、球落定后不弹结算弹窗，结果直接显示在 5.3 的"奖励数显示区域"——命中显示"获得 N 颗弹珠 + M 张积分卡"（伴积分卡出卡动画），未命中显示"本局投入 X 颗已沉没"；同区提供"再来一局 / 看视频 ×2（限频）/ 去商城"按钮（非弹窗，常驻于结果区或底部操作条）。常驻"领珠"按钮随时可点领 88 颗。命中时奖励珠以珠子逐颗掉落入"出珠盒子区域"的动画呈现（详见 5.3"出珠盒子区域动画"），出满奖励珠数 N；盒子满载后继续掉落则由物理引擎驱动溢出滚落。按钮主/次层级见 5.4。
  • 广告触发：领珠—玩家点常驻"领珠"按钮看视频领 88 颗（每日 6 次）；翻倍—命中结果区"看视频 ×2"；均走服务端回调发奖。
  • 商城 / 兑换：分层标签（虚拟 / 实物），商品卡显示积分价与"是否够兑"；兑换 → 风控 → 扣积分 → 下单 → 订单状态。

信息展示规格（已确认）

  • 投珠数：投珠面板大数字显示当前投入（默认 5，±/滑块 5–99，"最大"快捷），下方"本局命中预计得珠 = 投入 × 倍数"；局内 HUD 顶部"本局投入：X 颗"，加注后变"有效投入：X 颗"并高亮跳动。
  • 倍数：整局单倍数（沿用 4.3），开局后以醒目大字展示（如板顶"本局 ×8"）；亮灯出口仅高亮"可中区"，不重复标倍数；暗口置灰。
  • 结果奖励数（无弹窗，直接展示）：命中时奖励区直接显示"获得 N 颗弹珠"（N = 有效投入 × 倍数；看视频 ×2 后刷新为翻倍值）+ "M 张积分卡"，伴积分卡出卡动画；未命中明确"本局投入 X 颗已沉没"（透明合规）。展示区常驻"再来一局 / 看视频 ×2 / 去商城"与"领珠"按钮。
  • 出珠盒子区域动画（已确认）：板面底部设"出珠盒子区域"作为命中奖励珠的落点容器。命中后，珠子从落定的亮灯出口逐颗掉落入出珠盒子，每掉入一颗盒子计数 +1，直到累计达到奖励珠数 N（出满）；数字随之实时刷新。
    • 溢出（物理驱动）：盒子设容量上限 60 颗（显示用，见数值设计文档 §6）。奖励珠数超过该上限时，超出部分由物理引擎驱动溢出——溢出的珠子为真实 Box2D 动态刚体，与 4.6/4.7 同一物理世界（板面局部坐标、局部竖直重力），碰撞盒壁、沿盒沿滚落消散，非脚本动画；入账以服务端为准，盒子不得因溢出丢失应得奖励。
    • 未命中的暗口通道（沉没）：未命中时球落入与出珠盒子隔离的"沉没通道"（暗口），不进入出珠盒子，结果区显示"本局投入 X 颗已沉没"。亮灯出口与暗口在几何上分属不同通道，避免玩家误以为"掉珠却没奖"。
    • 看视频翻倍的补播：命中后点"看视频 ×2"，奖励数刷新为 2N，出珠盒子补播掉落额外 N 颗（同样走容量上限与物理溢出逻辑），数字累加至 2N。
    • 性能约束：奖励珠数 N 可能很大（如投入 99×20=1980），不逐颗生成全部 N 个物理刚体；演出仅生成有限数量物理珠（容量上限 60 + 溢出若干），数字计数器累加至 N，保证移动端帧率。
    • 下落节奏：按 N 分级（N 小则快落，N 大则连续喷落并加速），保持爽感且不拖时长。
  • 剩余出珠数（弹珠余额）：HUD 右上常驻"弹珠：N"，结算后 N 实时 −投入 / +奖励，带数字滚动动画。
  • 图层关系：上述文字 HUD 与拉杆 / 加注按钮属屏幕正向独立图层，不随 4.7 的 30° 板面旋转；板面仅承载钉板、亮灯出口与球体演出。

结果展示区按钮层级（已确认 · 方案甲）

  • 命中后结果区含三类动作：看视频 ×2 翻倍、再来一局、去商城 / 分享。已采用方案甲：主按钮 = "看视频 ×2"（最大最亮，冲广告收益、观看率最高；连玩时玩家需先经过广告，留存靠钉板手感与"再来一局"强次按钮兜底）。方案乙（主按钮 = "再来一局"，冲留存）作为备选，可在留存数据变差时切换评估。
  • 未命中时结果区仅含"再来一局 / 去商城"，不含翻倍广告按钮；常驻"领珠"按钮（领 88 颗）始终可用，不依赖弹窗。
  • 频控提示：领珠/翻倍按钮常驻显示"今日剩 N 次"；当日额度用尽则按钮置灰并提示"今日已达上限，明天再来"，不触发视频。

6广告变现需求

6.1 广告场景（激励视频为核心）

场景触发时机奖励频控（初始）
弹珠续命（领珠）点常驻"领珠"按钮（主动领取）+88 颗每日 6 次
中奖翻倍命中亮灯出口结算时本局奖励 ×2每局 1 次 / 每日 10 次
签到翻倍每日签到后签到奖励 ×2每日 1 次
高倍挑战入场解锁 ×15/×20 专场进入高倍模式 3 局每日 3 次

6.2 广告体验原则

  • 所有广告均为玩家主动选择换收益，无强制插屏打断拉杆/结算核心操作。
  • 发奖统一走服务端 server verify 回调，客户端不信任本地"已看完"状态。
  • 单用户单日激励视频总次数封顶（初始 20 次）。
  • 小游戏端用微信流量主激励视频；App 端用穿山甲/聚合广告；游戏逻辑层不感知具体平台（SDK 隔离封装）。

6.3 展现与频控

  • 续命/翻倍入口按钮带"视频"图标与倒计时/次数提示。
  • 达到当日次数上限时按钮置灰并提示"明日再来"。

6.4 埋点（广告漏斗）

  • 曝光 → 点击播放 → 完播 → 服务端回调成功 → 发奖成功，逐环节埋点（见第 8 节）。

6.5 经济模型闸门 P0

不亏损护栏：运营后台实时监控 人均广告观看次数 × eCPM ÷ 人均积分产出成本。比率低于安全阈值（≥1.2）时，自动/人工收紧积分产出（下调 RTP、上调积分卡门槛），保证广告收益覆盖奖品成本。该闸门是产品能否长线盈利的硬约束。

7积分商城与实物兑换

7.1 商品结构（按兑换所需卡数 K 分层）

  • 虚拟引流档（K=5）：+50 弹珠 / 表情 / 皮肤（成本≈0，利润与留存引擎，常驻可见）。
  • 小实物档（K=20）：贴纸 / 书签 / 卡套（¥1~2）。
  • 中实物档（K=50）：文具 / 盲盒 mini（¥3~4）。
  • 实物主档（K=80）：盲盒 / 周边小物（¥5~6，核心转化档）。
  • 高实物档（K=120）：周边 / 小玩具（¥8~10，满足感档）。
  • K 分层由《玩法数值设计文档》仿真定为满足生命线；重度玩家攒 80 卡约 0.4 天 / 轻度约 3 天可兑一件主档实物。
  • 兑换单位说明：商城兑换门槛以"所需积分卡张数 K"标注；因 1 张积分卡 = 10 积分，亦等价于"所需积分数 = K×10"。玩家视角只看到 K 张卡，无需理解底层积分。

7.2 兑换订单状态机

created→risk_checked→deducted→fulfilling→done / failed→退积分

  • 扣积分必须在事务内完成，履约失败需回退积分（幂等 + 补偿）。
  • 实物需收货信息；虚拟券直充手机号/账号。

7.3 关键规则

  • 兑换限额：单用户每日/每月兑换上限；高价值商品需累计活跃天数门槛。
  • 全流程流水可审计，订单与积分变动一一对应。
  • 第三方兑奖平台对接：话费券 / 电商卡 / 实物代发，无自有库存压力。

7.4 商城体验需求

  • 商品列表按门槛分层、缺货/下架状态清晰；兑换按钮实时显示"积分是否足够"。
  • "我的订单"展示状态与（实物）物流进度。

8数据与埋点需求

8.1 核心指标

  • 规模/留存：DAU、次留、7 留。
  • 活跃/参与：人均局数、人均拉杆次数。
  • 变现：人均激励视频次数、eCPM、广告 ARPU。
  • 经济：积分产出成本、兑换率、LTV / CAC。

8.2 埋点漏斗

漏斗环节
局内漏斗开局 → 加注 → 拉杆 → 结算命中
广告漏斗曝光 → 点击播放 → 完播 → 回调成功 → 发奖成功
兑换漏斗浏览商品 → 点击兑换 → 风控通过 → 扣积分 → 履约完成

8.3 运营后台需求（P0）

  • RTP 与倍数池配置、弹珠发放配置、商城上下架、订单管理、风控名单、数据看板。
  • 经济闸门阈值配置与告警。

9合规与风控需求

9.1 合规红线（必须满足）

  1. 弹珠不可现金购买，切断"花钱 → 随机 → 实物"的博彩链路。
  2. 积分与奖品不可逆向兑换成现金。
  3. 概率公示：倍数档位与出现概率在游戏内可查。
  4. 未成年人防沉迷与消费提示。
  5. 遵守微信小游戏平台关于抽奖类玩法与实物发放的审核规范。

9.2 风控需求

  • 防刷：设备指纹 + 账号行为画像；广告回调去重；同 IP/同设备多账号限制。
  • 防外挂：结果服务端判定使物理外挂无效；接口签名 + 时间戳防重放。
  • 羊毛党：兑换前实名/手机号校验，异常账号进入人工审核队列。
  • 并发安全：开局锁定投入、结算幂等（同一局多次回调只结算一次）。

11验收标准（P0 首发）

  • ✅ 微信小游戏可登录、可正常进行完整一局（开局→加注→拉杆→结算）。
  • ✅ 倍数与落口由服务端决定，客户端无法伪造中奖结果。
  • ✅ 激励视频发奖必须经服务端回调验证，伪造"看完"不发奖。
  • ✅ 每日登录赠珠 30 颗、激励视频领珠 88 颗/次（每日 6 次）正常发放与限频。
  • ✅ 积分卡规则：单局命中奖励珠 R ≥ 40 才发卡（卡数 = min(5, floor(R/40))）、兑换按所需卡数 K 分层（5/20/50/80/120），积分账本正确且不可逆流。
  • ✅ 商城兑换全流程（风控→扣积分→第三方履约→订单状态）跑通，失败可退积分。
  • ✅ 游戏内可查倍数概率公示；未成年提示存在。
  • ✅ 经济闸门可配置并触发收紧逻辑。
  • ✅ 广告/局内/兑换三大漏斗埋点完整，后台看板可见。
