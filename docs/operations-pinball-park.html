2运维与部署

  • 服务：Go（Gin/chi）+ GORM/sqlx；MySQL（Append-Only 账本 bean_ledger/point_ledger）+ Redis（会话/game_lock/日计数/频控）；容器化、多可用区、无单点。
  • 参数外部化：RTP（含新手保护曲线）、倍率权重、K 分层、广告 eCPM、频控上限全部配置化，支持热更新；调整后须经经济回归（数值 §3 / 测试 NUM-09）再下发。
  • 对账：每日 bean_ledger + point_ledger 与余额快照对账，差异 >0 即告警并人工介入（测试 §10）。
  • 容灾：game_lock TTL 30min 自动释放并回滚（open_refund），防崩溃死锁（API §3 / 测试 FUN-09）。

4经济运营（核心）

目标：守住经济生命线 广告收益 ≥ 积分成本 × 1.2。[评审修订 v1.3] 数值 v1.2 原称"K=80 重度/轻度均 1.38×"，但该结论未计入每日 20 次视频频控，已作废；真实约束下当前默认参数（eCPM=0.30）全面破防，须将 eCPM 目标校准至 ≥0.55（或等效组合）方可达标（见数值 §3.2/§8）。运营动作优先级：先调 K 与广告 eCPM，再考虑抬发卡门槛（用户偏好"体验优先"，卡要易触达）。

杠杆作用调节纪律
K 分层（5/20/50/80/120）直接改积分卡"含金量"，保生命线eCPM 走弱时优先升 K（如 80→100），不抬 40 门槛[评审修订：原"降 K"方向错误，已更正]
广告 eCPM / scene提升广告侧收入（sign / high_multiplier 触发点优化）A/B 优化触发时机与填充率
倍率权重微调均倍与手感改动必跑 NUM 回归（测试 §3）
新手保护曲线前 5 局 RTP 1.5 递减至 0.90 留存稳态不允许长期偏离 0.90
免费珠池登录 30 + 领珠 88×6 = 558/日，控日活成本领珠每日 ≤6 次强频控
任何经济参数变更必须：① 经 docs/sim/economy_sim.py 重跑确认生命线 ≥1.2×；② 经灰度观察真实 A/C；③ 对账无误后再全量。禁止凭直觉调参。

5活动与增长

  • 日常：登录发珠、激励视频领珠（88/次 ×6）、高倍挑战场（×16/×32 专场解锁）。
  • 赛季 / 活动：限时倍率加成、连胜奖励、节日主题机台皮肤（纯表现，不影响 RTP）。
  • 防沉迷：未成年时段限制 + 频次约束；广告与领珠对未成年差异化处理（合规 §7）。
  • 社交（后续）：排行榜、好友赠珠——需重新评估经济模型，不在首发范围。

6风险与应急

风险迹象应急预案
RTP 偏离实时 RTP 偏离 >±3%定位权重配置 → 热修复 → 回滚至基线 0.90
刷奖攻击单用户异常高频局 / 异常大额风控限流 + 审计 + 人工冻结；命中仅服务端权威（测试 SEC-03/04/08）
生命线破防A/C < 1.2× 持续先降 K → 再优化 eCPM → 极端情形抬门槛，按 §4 纪律
服务宕机接口 5xx 飙升多可用区切换；game_lock TTL 保资产不丢；恢复后断线重连重放
数据不一致对账差异 ≠0暂停放量；按账本流水补差；定位双写失败点
广告回调异常发奖失败率突增平台侧排查 + 客户端补发兜底（以 server verify 为准）
价值安全红线（同测试 §5）：弹珠/积分卡/广告发奖的权威值只来自服务端。任何客户端篡改、伪造回调、并发重放均不得改变入账结果，违者按 P0 处置。
