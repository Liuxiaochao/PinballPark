# 弹珠乐园 · 游戏界面重构设计

日期：2026-08-03
状态：待审阅

## 1. 背景与目标

当前项目存在两类问题：

1. 现有界面文档与已实现原型脱节，文档描述“5-99 颗投注、可加注、无结算弹窗、30° 后仰”，当前代码是固定 1 颗、无加注、结算弹窗、60° 后仰。
2. 界面问题散落在 PRD、UI-UX、架构、代码里，后续 AI 需要同时读多份文档才能定位问题。

本次目标：

- 玩法规则和数值规则不改变。
- 对当前已实现界面做一次完整重构设计。
- 基于讨论结果生成一份独立、详细、可快速排查问题的权威界面文档：`docs/ui/game-interface.html`。

## 2. 非目标

- 不修改 PRD、数值设计、功能卡的玩法/数值结论。
- 不纳入未实现页面：商城、我的/订单、新手引导、社交裂变。
- 本设计不包含音效素材生产、美术切图生产、服务端接口实现。
- 本设计不要求在本次文档阶段重构客户端代码；代码重构属于后续实施。

## 3. 已确认设计决策

| 主题 | 决策 |
|---|---|
| 整体气质 | 街机实感 |
| 信息架构 | 全屏机台优先，不保留独立大厅页 |
| 机台布局 | 整机一体：顶部招牌 + 中部弹珠板 + 底部控制台 |
| 系统入口 | 左侧抽屉：任务、商城、概率公示、设置 |
| 快捷入口 | 顶部招牌下保留“领珠 +88” |
| 投注入口 | 底部控制台集成 |
| 开局 | IDLE 态点“开始”，自动投入 5 颗，进入可加注/可发射态 |
| 加注 | 每次 +1 颗，支持快速连点；按住连续加，上限 99 且受余额约束 |
| 结算 | 吐票结算带，不弹窗 |
| 发射 | 按住蓄力、松开发射，支持取消 |
| 透视参数 | 界面文档标为“可配置”；暂以当前代码 60° 为基线，并标记待人工统一 |

## 5. 界面信息架构

整套界面以单台弹珠机为外壳：

- 顶部招牌：品牌 LED 跑马灯。
- 招牌下状态行：弹珠余额、领珠 +88、积分卡。
- 中部弹珠板：钉阵、发射通道、倍数/亮灯出口、出珠盒、沉没区。
- 左边缘：抽屉触发边。
- 底部控制台：`投入 5` + `加珠 +1` + `按住拉杆`。
- 结果态：吐票结算带从机台下部滑出。

左侧抽屉内容：

- 每日任务
- 商城
- 概率公示
- 设置

商城作为抽屉入口保留，但商城页面本身不属于本次界面文档范围。

抽屉和顶部领珠只在非阻塞状态开放。

## 6. 主屏状态机

```text
IDLE_START
  → 点“开始”/自动扣 5 → STARTING
  → 服务端返回倍数+亮灯 → BET_READY
  → 按住拉杆 → CHARGING
  → 松手发射 → SIMULATING
  → 落定 → RESULT_TRAY
```

状态转移规则：

| 状态 | 主行为 | 可用入口 | 禁用内容 |
|---|---|---|---|
| IDLE_START | 开始游戏 | 抽屉、领珠 | 发射、加珠 |
| STARTING | 等待开局 | 无 | 所有操作 |
| BET_READY | 加珠、发射 | 抽屉、领珠 | 无 |
| CHARGING | 蓄力/取消/发射 | 无 | 抽屉、领珠、加珠、投注 |
| SIMULATING | 球飞行 | 无 | 所有操作 |
| RESULT_TRAY | 再来 / ×2 / 商城 | 抽屉、领珠 | 主屏控制台 |

补充规则：

- 取消蓄力回 `BET_READY`，不扣珠、不请求服务端。
- 结果态“再来”直接再扣 5 颗进 `STARTING`。
- 看视频 ×2 只翻弹珠奖励，积分卡不重复发。

## 8. 状态细则

### IDLE_START

- 底部控制台显示：`投入 5`（只读）、`开始`（主按钮）。
- 顶部领珠、左抽屉可用。
- 弹珠板播放待机演示，不显示本局倍数，不扣珠。

### STARTING

- 点“开始”后按钮变“开局中”，自动扣 5 颗。
- 服务端返回倍数和亮灯出口后才进入 `BET_READY`。
- 失败时 Toast 并回到 `IDLE_START`。

### BET_READY

- 底部控制台显示：`投入 5`、`加珠 +1`、`按住拉杆`。
- `加珠 +1` 每点一次加 1 颗，支持快速连点；按住连续加。
- 总投入上限 99，且不能超过弹珠余额。
- 有效投入和“预计得珠 = 投入 × 当前倍数”实时刷新。
- 抽屉和领珠可用。

### CHARGING

- 按住蓄力，弹珠板/发射杆同步反馈。
- 松手发射。
- 移出发射热区或拖入取消区松手为取消，不扣珠、不请求服务端，回 `BET_READY`。
- 蓄力期间抽屉、领珠、投注、加注全部禁用。

### SIMULATING

- 球飞行期间所有游戏控件禁用，不弹窗。

### RESULT_TRAY

- 吐票结算带滑出。
- 命中显示奖励和积分卡；沉没显示明确沉没文案。
- 命中按钮：`看视频 ×2`、`再来`、`去商城`。
- 沉没按钮：`再来`、`去商城`。
- 抽屉和领珠可用。

## 9. 交互与动效规格

| 交互 | 规格 |
|---|---|
| 蓄力发射 | 按住填充约 1.4 秒满；松手发射 |
| 取消 | 移出热区/拖入取消区松手即取消 |
| 加珠 | 单击 +1；按住约 100ms 间隔连续加 |
| 吐票结算带 | 260ms 从机台下部滑出，不弹窗 |
| 左抽屉 | 200ms 从左侧滑出，机台压暗 |
| 顶部领珠 | 显示今日次数；验真后 +88 数字滚动 |
| 亮灯出口 | 服务端返回后 200ms glow 点亮 |
| 看视频 ×2 | 结果带内 N 翻到 2N，按钮禁用 |
| 按钮按压 | 按下 scale 0.96 + 亮度变化，回弹约 80ms |

## 10. 音效、触觉与微信适配

音效：

- 按钮、开始、蓄力、松手发射、球碰钉、落出口、吐票、积分卡、命中、沉没、抽屉开合、领珠到账。

触觉：

- 发射、落口、命中、沉没使用 `wx.vibrateShort` 轻震动。
- 连点加珠不逐次震动。

微信适配：

- 720×1280 竖屏。
- 顶部避让微信胶囊，底部避让安全区。
- 机台四角保留安全内边距。

触控热区：

- `开始`、`加珠 +1`、`按住拉杆`、领珠、抽屉触发边至少 88×88 设计像素。
- 取消区明显且可独立命中。

## 11. 问题发现机制

目标文档必须包含：

- 每个界面的“规范 / 验收 / 常见问题”三块。
- 代码映射表：
  - `Main.ts`：场景入口
  - `PinballGame.ts`：机台/状态
  - `UI.ts`：UI 工厂
  - `GameConfig.ts`：参数
  - `BallController.ts`：物理回调
  - `ExitTag.ts`：出口标签
  - `MockBackend.ts`：本地账本
- 问题登记模板：现象、复现步骤、期望、实际、影响、涉及文件/节点、优先级。
- AI 排查流程：定位界面 → 找到状态 → 对照分区/控件/交互 → 核对代码映射 → 登记问题。
- 已知迁移差异清单：当前代码的结算弹窗、固定 1 颗、无加注、无抽屉等。
